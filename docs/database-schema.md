# Развёртывание базы данных

## Параметры

| Параметр | Значение |
| --- | --- |
| Название базы | AuctionDesk |
| SQL Server | Microsoft SQL Server 2022 (проверено на экземпляре `DESKTOP-MTDRK23`) |
| Аутентификация | Windows Authentication (Integrated Security=true) |
| Инструмент выполнения скриптов | SQL Server Management Studio (SSMS) 22 |

## Порядок выполнения

База создаётся внутри `schema.sql`, отдельное создание базы вручную не требуется.

Откройте SSMS и подключитесь к своему экземпляру SQL Server через Windows Authentication. Для LocalDB используется сервер `(localdb)\MSSQLLocalDB`, для SQL Server Express — `localhost\SQLEXPRESS` или имя компьютера. Имя текущего экземпляра возвращает запрос `SELECT @@SERVERNAME`.

Убедитесь, что пользователь Windows имеет права на создание баз данных.

Выполните `schema.sql` для создания базы, таблиц, ключей, ограничений, индексов и представления `vw_lot_report`. Скрипт создаёт 5 таблиц: `users`, `categories`, `lots`, `bids`, `winners`.

Выполните `seed.sql` для наполнения тестовыми данными.

Проверьте результат запросами:

```sql
USE AuctionDesk;
SELECT TABLE_NAME FROM INFORMATION_SCHEMA.TABLES WHERE TABLE_TYPE = 'BASE TABLE' ORDER BY TABLE_NAME;
```

Ожидаемый список: `bids`, `categories`, `lots`, `users`, `winners`.

```sql
SELECT N'users' AS таблица, COUNT(*) AS записей FROM users
UNION ALL SELECT N'categories', COUNT(*) FROM categories
UNION ALL SELECT N'lots', COUNT(*) FROM lots
UNION ALL SELECT N'bids', COUNT(*) FROM bids
UNION ALL SELECT N'winners', COUNT(*) FROM winners;
```

Ожидаемые значения: 5, 5, 5, 13, 2.

Настройте приложение по основному [README](../README.md).

## Повторный запуск

`schema.sql` пересоздаёт базу с нуля: если база `AuctionDesk` существует, она переводится в однопользовательский режим, удаляется командой `DROP DATABASE` и создаётся заново. Все данные, введённые через приложение, при этом теряются. Скрипт следует запускать только при необходимости полного сброса структуры.

`seed.sql` можно выполнять повторно: он очищает таблицы в порядке, обратном зависимостям по внешним ключам (`winners`, `bids`, `lots`, `categories`, `users`), и вставляет тестовый набор заново. Структура базы при этом не меняется.

Рекомендуемый порядок сброса: `schema.sql`, затем `seed.sql`.

## Тестовые данные

Набор тестовых данных включает следующие сущности:

- **users** (5 записей) — участники аукциона: ivan_petrov, maria_ivanova, alexey_smirnov, elena_kuznetsova, dmitry_volkov. Используются для смены текущего пользователя и проверки ролей продавца и покупателя.
- **categories** (5 записей) — категории лотов: Искусство, Антиквариат, Электроника, Коллекционирование, Ювелирные изделия. Используются для фильтрации и группировки в отчёте.
- **lots** (5 записей) — Картина «Закат» (600 с), Старинные часы (300 с), iPhone 15 Pro (120 с), Коллекция марок и Золотое кольцо. Первые три активны с разным оставшимся временем, последние два завершены и имеют заполненную дату окончания и победителя.
- **bids** (13 записей) — ставки по всем лотам, по несколько ставок на лот, что позволяет проверить определение максимальной ставки.
- **winners** (2 записи) — победители завершённых лотов: Коллекция марок (4500 ₽) и Золотое кольцо (32000 ₽).

## Настройка подключения

Строка подключения хранится в файле `src/AuctionDesk.App/Data/Database.cs` в свойстве `ConnectionString`:

```csharp
public static string ConnectionString { get; } =
    @"Server=DESKTOP-MTDRK23;Database=AuctionDesk;Integrated Security=true;TrustServerCertificate=true;";
```

При переносе на другой компьютер меняется только значение `Server=` — имя экземпляра SQL Server. Имя базы, способ аутентификации и остальные параметры остаются прежними. Пароли не используются: применяется Windows-аутентификация, поэтому файл-пример с секретами не требуется.

Используйте SQL-скрипты как воспроизводимый источник структуры и учебных данных. Файлы базы `.mdf`, `.ldf` и резервные копии не заменяют скрипты. Не привязывайте развёртывание к абсолютным путям своего компьютера.
